Part VIII Failure Recovery & Audit Discipline

AgriSense strictly enforces controlled fallback mechanisms and failclosed paths. If an external API fails (such as Geoapify geocoding or rate-limited Gemini LLM keys), the system uses explicit, approved fallbacks without inventing data or hallucinating unverified weather.

Controlled Geolocation Fallback

GEOAPIFY → GAZETTEER
1. PRIMARY CALL: Geoapify Geocoding API Request: geocode_location("Shibchar, Madaripur") → Timeout / Provider Error
2. RECOVERY ACTION: Approved Gazetteer Fallback Lookup: mock_location_centroids.json → Centroid (23.3500°, 90.1500°)
3. RESULT: Plan Weather Weather Grounded Weather API called with verified centroid coordinates. Plan remains grounded.

LLM Rate Limit Failover (429 Recovery)

4-KEY POOL
1. PRIMARY CALL: Key #1 Gemini generateContent → HTTP 429 RESOURCE_EXHAUSTED
2. RECOVERY ACTION: Instant Key Rotation Key #1 put into 15s cooldown → Key #2 acquired instantly
3. RESULT: Zero User Interruption Turn executes seamlessly at 45+ req/min aggregate capacity.
